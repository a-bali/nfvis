# Release and container publishing

The `Container images` GitHub Actions workflow publishes to `ghcr.io/<owner>/<repository>` (the name is normalized to lowercase by the metadata action). Pushes to `main` publish `dev` and a commit-specific `dev-<short-sha>` image. Push a `vMAJOR.MINOR.PATCH` Git tag to publish the version and minor-series tags and `latest`; prerelease tags publish only their full version, never `latest`. Version tags should be immutable. The image embeds its tag (or development commit) in `nfvis --version`.

Before tagging: review CI and [release risks](release-review.md), validate decoded totals against a known transfer, test migration and restore on a copy of a representative database, and ensure `config.yaml`, databases, credentials and other local files are not committed. The existing local `v0.1` tag is not accepted by the image workflow and predates the current release; use an immutable three-component tag such as `v0.1.0` for the validated release. Publish a GitHub Release from the tag with upgrade and rollback notes. Image visibility is controlled in GitHub Packages; a newly published package may be private by default. The repository's default branch must be named `main` or the workflow branch filter must be adjusted.

Local builds: `make build VERSION=v1.2.3`; `./nfvis --version`. Container: `docker build --build-arg VERSION=v1.2.3 -t nfvis:v1.2.3 .`.

The image runs as a non-root user (UID/GID 10001) and uses `/data` for its configuration and database. Mount a writable directory owned by that user and a configuration file at `/data/config.yaml`. Override the command to use another path. The default HTTP listener is `127.0.0.1:8080` inside the container: configure `listen.http: 0.0.0.0:8080` for published ports, and protect it with a trusted network or authenticated TLS reverse proxy. UDP should be published explicitly, e.g. `-p 2055:2055/udp`. The app has no built-in authentication or TLS. Use `docker run --rm -p 127.0.0.1:8080:8080 -p 2055:2055/udp -v /path/to/data:/data ghcr.io/OWNER/REPO:dev` after preparing the mount and configuration.
